# 家族麻雀 スコア記録

麻雀のスコアを登録・集計する Google Apps Script Web アプリ。
データは Google スプレッドシートに保存され、PC/スマートフォンのブラウザから
URLへアクセスして利用できます。

以下はブラウザに表示される画面のサンプルです。実際の画面はスマートフォンの幅の縦長で、
ここには各タブの上端から1画面分だけを載せています。続きを含めて見るには
**[画面サンプル（タブ切り替え）](https://shintarominami.github.io/Family_Mahjong_Record/)**
をどうぞ。

![登録・今日・履歴・統計・設定の各タブ](docs/screens.png)

*四麻200半荘＋三麻100半荘のサンプルデータを入れた状態。*

## できること

- **登録** — 1半荘ごとに、プレイヤー・素点・チップを入力。素点合計をリアルタイム検証し、
  確定前に順位と収支をプレビュー。
- **今日** — その日の対局一覧と、四麻・三麻に分けたプレイヤー別集計。
- **履歴** — 期間で絞った対局一覧。誤入力の訂正・削除。
- **統計** — 通算成績（対局数・平均順位・着順分布ほか）と、着順ごとの率・トビ率・
  平均素点をまとめた詳細表、成績の推移グラフ。
- **設定** — ルールプリセットの管理。人数（4人/3人）・配給原点・返し点・ウマ・飛び賞を
  それぞれ独立に設定。パスワードの変更。画面の配色とタブバーの表示の変更（端末ごとの個人設定）。
- 4人麻雀 / 3人麻雀の両対応。ウマ・オカ・飛び賞・チップに対応。
- ルールを変更しても、登録済みの対局は登録時のルールのまま集計されます。
  （対局ごとにルールのスナップショットごと保存）
- **パスワードによる簡易的なアクセス制限**。`setup()` が発行し、初回アクセス時に入力を求めます。

## はじめる

### Google Apps Script での公開

自分の Google アカウントの中だけで完結するブラウザベースのアプリケーションを作成し、公開します。
**サーバーの用意や月々の費用などは不要**です。

- **画面** — Apps Script の Web アプリとして公開します。`doGet` が単一ページを返し、
  ブラウザからは `google.script.run` でサーバー側の関数を呼びます。
- **データ** — `setup()` が自分の Google Drive に作るスプレッドシート1つ。中身は普通のデータシートなので、必要なら直接開いて編集することもできます。
- **公開範囲** — 「全員（匿名アクセス可）」で公開し、URLを知っている人はアクセスできる、という運用を想定しています。念のため非常に簡易的なパスワードを設定しています。サーバー側の処理はデータシートのみに影響し、その他のドライブ内のデータは一切共有しません。

### 前提としている技術スタック

`src/` に置いた JavaScript と HTML/CSS がそのまま動きます。実行時の外部依存はなく、Apps Script のランタイムだけで完結します。

| | |
|---|---|
| 使うのに必要 | Google アカウント（デプロイする人だけ） |
| 開発・デプロイに必要 | Node.js と npm。ローカルサーバー・テスト・`clasp` の実行に使います |
| 型チェック | JSDoc コメント＋TypeScript |
| デプロイ | [clasp](https://github.com/google/clasp)（`npm install` で入ります） |

### 手順

自分で立てて使う場合は **[SETUP.md](SETUP.md)** を参照（カスタマイズ → デプロイ →
パスワード → 更新の手順）。設計や内部の細かな仕様は [DESIGN.md](DESIGN.md)。

まず動かしてみるだけなら、Google へのデプロイなしにブラウザでローカルに確認できます。

```bash
npm install        # 型定義・TypeScript・clasp のみ。実行時依存なし
npm run dev:bulk   # 四麻200半荘＋三麻100半荘のサンプルデータで起動
# → http://localhost:8080
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 現在のローカルDBのまま起動 |
| `npm run dev:seed` | データが空ならサンプルを投入して起動 |
| `npm run dev:reset` | ローカルDBを作り直して6半荘だけ投入 |
| `npm run dev:bulk` | ローカルDBを作り直して5人・四麻200半荘＋三麻100半荘を投入。統計やグラフの確認用 |

対局数は `--games4` / `--games3` で指定します（npm 経由では `--` を挟んで
`npm run dev -- --reset --seed --games4 50 --games3 20`）。

ローカルDBは `dev/data/db.json`（Git管理外）。スプレッドシートの行をそのまま配列で
持つので、本番と同じ読み書き経路を通ります。`src/` を編集すると次のリクエストで
読み直されます。

## テスト

```bash
npm test           # 計算・集計・書き込み無害化・設定・サーバーAPIの78件
npm run test:e2e   # ヘッドレスChromeで実UIを操作する2シナリオ107項目
npm run test:all   # 両方
npm run typecheck  # JSDocベースの型チェック
```

`npm test` は `src/` の実コードを Node に読み込んで検証します。
`npm run test:e2e` は Chrome を自動で探し、見つからなければスキップします
（`CHROME_PATH` で明示指定も可）。

## ディレクトリ構成

```
src/          Apps Script にデプロイされるコード
  Config.js     タイトルなど、自分用に決める設定
  Code.js       doGet / setup（エントリポイント）
  Schema.js     シート定義と値の正規化
  Domain.js     順位・ウマ・オカ・収支の計算（関数）
  Stats.js      集計（関数）
  Store.js      スプレッドシートへの読み書き
  Repo.js       ドメイン単位のCRUD
  Auth.js       パスワードの検証
  Api.js        ブラウザから google.script.run で呼ぶ関数
  index.html / css.html / js.html   画面
  appsscript.json   マニフェスト（公開範囲・タイムゾーン）
dev/          ローカル開発用（デプロイされない）
  local-server.js  ローカルWebサーバー
  app-context.js   src/*.js をNodeに読み込む
  LocalStore.js    Store.js のローカル版（JSONファイル）
  server.js        HTTP層
  deploy.js        push とデプロイ更新をまとめて実行
  calibrate-seed.js   サンプルデータのチェック
  e2e-script.js       ブラウザ内E2Eシナリオ
  e2e-gate-script.js  パスワード画面のE2Eシナリオ
tests/        テスト
```
