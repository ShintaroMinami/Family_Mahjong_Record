# 家族麻雀 スコア記録

家族の麻雀（実卓中心）のスコアを登録・集計する Google Apps Script Web アプリ。
データは Google スプレッドシートに保存され、スマートフォンのブラウザから
URL ひとつで利用できる。

設計の詳細は [DESIGN.md](DESIGN.md) を参照。

## できること

- **登録** — 1半荘ごとに、席順・素点・チップを入力。素点合計をリアルタイム検証し、
  確定前に順位と収支をプレビュー
- **今日** — その日の対局一覧とプレイヤー別集計
- **履歴** — 期間で絞った対局一覧。誤入力の訂正・削除（論理削除）もここから
- **統計** — 通算成績（対局数・平均順位・着順分布・連対率・トップ率・ラス率・トビ率・
  平均素点）と推移グラフ。表は見出しをタップして好きな列で並べ替えられ、グラフは
  合計・平均・平順・チップを切り替えられる
- **設定** — ルールプリセットの管理。人数（4人/3人）・配給原点・返し点・ウマ・飛び賞を
  それぞれ独立に設定でき、オカとウマ合計は自動計算して検証される。配色（6色）と
  タブバーの表示（アイコン/絵文字/文字のみ）も選べる（端末ごとの設定。明暗はOSに従う）
- 4人麻雀 / 3人麻雀の両対応。ウマ・オカ・飛び賞・チップに対応
- ルールを変更しても、登録済みの対局は**登録時のルールのまま**集計される
  （対局ごとにルールのスナップショットを保存）
- 雀魂の牌譜IDを任意で保存し、牌譜へのリンクを生成
- **パスワードによるアクセス制御**。`setup()` が発行し、初回アクセス時に入力を求められる

## ディレクトリ構成

```

  Config.js     タイトルなど、自分用に決める設定
  Code.js       doGet / setup（エントリポイント）
  Schema.js     シート定義と値の正規化
  Domain.js     順位・ウマ・オカ・収支の計算（純粋関数）
  Stats.js      集計（純粋関数）
  Store.js      スプレッドシートへの読み書き
  Repo.js       ドメイン単位のCRUD
  Auth.js       パスワードの検証
  Api.js        ブラウザから google.script.run で呼ぶ関数
  index.html / css.html / js.html   画面
dev/          ローカル開発用（デプロイされない）
  local-server.js  ローカルWebサーバー
  app-context.js   src/*.js をNodeに読み込む
  LocalStore.js    Store.js のローカル版（JSONファイル）
  server.js        HTTP層
  deploy.js        push とデプロイ更新をまとめて実行
  calibrate-seed.js   サンプルデータの実力差・分散を実測する
  e2e-script.js       ブラウザ内E2Eシナリオ
  e2e-gate-script.js  パスワード画面のE2Eシナリオ
tests/        テスト
```

## ローカルで動かす

Google へのデプロイなしに、ブラウザで動作確認できる。

```bash
npm install          # 型定義と clasp のみ。実行時依存はゼロ
npm run dev:reset    # サンプルデータ付きで起動（既存のローカルDBは消える）
# → http://localhost:8080
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 現在のローカルDBのまま起動 |
| `npm run dev:seed` | データが空ならサンプルを投入して起動 |
| `npm run dev:reset` | ローカルDBを作り直してサンプルを投入（6局） |
| `npm run dev:bulk` | 5人・四麻200局＋三麻100局。統計やグラフの見え方を確かめる用 |

局数は `--games4` / `--games3` で指定する
（`npm run dev -- --reset --seed --games4 50 --games3 20`）。どちらも指定しなければ
固定の6局になる。乱数は固定シードなので、同じ指定なら毎回同じデータになる。

生成データには**実力差が付けてある**。強い順に 妹・祖父・父・母・兄。
四人麻雀での狙いは次のとおりで、`node dev/calibrate-seed.js` で実測できる。

| 項目 | 値 |
|---|---|
| 平均順位 | 最強 2.20 → 最弱 2.80（間は等間隔） |
| 素点の標準偏差 | 約16,900点 |
| トビ率 | 約7% |

素点の散らばりとトビ率は実際の半荘の統計に近い値に合わせてある。実力差の刻みは
`SKILL_STEP`、順位は `SKILL_ORDER`（ともに `dev/app-context.js`）。

ローカルDBは `dev/data/db.json`（Git管理外）。スプレッドシートの行をそのまま
配列で持つので、本番と同じ読み書き経路を通る。

`src/` を編集すると、次のリクエストで読み直される（コンソールに
`src/ の変更を読み直しました` と出る）。ブラウザは再読み込みするだけでよい。

```bash
npm test           # 計算ロジック・集計・サーバーAPIの58件
```

## 自分用にカスタマイズする

デプロイ前に決めるのは `src/Config.js` の2つだけでよい。

```js
var APP_TITLE = '家族麻雀 スコア記録';   // タブ・画面見出し・スプレッドシート名
var DEFAULT_ACCENT = 'green';          // 配色の既定
var DEFAULT_ICONS = 'line';            // タブバーのアイコンの既定
```

`APP_TITLE` は、ブラウザのタブ・画面上部の見出し・`setup()` が作るスプレッドシートの
ファイル名をまとめて決める。

`DEFAULT_ACCENT` は、まだ自分で選んでいない人に出る配色。`green` `blue` `red`
`purple` `orange` `black` の6つから選ぶ。

`DEFAULT_ICONS` は下部タブバーの表示。`line`（アイコン）`emoji`（絵文字）
`text`（文字のみ）の3つ。アイコンはSVGの線画なので、どの環境でも同じ形で、
選択中はアクセント色になる。絵文字はOSによって見た目が変わり、選択中でも色が付かない。

どちらも使う人が設定タブから各自変更できる（端末ごとに記憶される）。存在しない id を
書くと配色は `green`、タブの表示は `emoji` にフォールバックするが、`npm test` が
検出して落ちる。

> `clasp create --title` で指定するのは **Apps Script のプロジェクト名**であって、
> アプリの表示名ではない。両者は無関係なので、`--title` を変えてもタブには
> `APP_TITLE` が出る。

**パスワードは自分で決めなくてよい**。`setup()` がランダムなものを1つ発行して
実行ログに出すので、それを家族に伝えるだけで運用を始められる。覚えやすいものに
変えたい場合は、公開後にアプリの設定タブから変更する（詳細は下記「パスワード」）。

スプレッドシートを先に作ってしまった後でタイトルを変えた場合、ファイル名は
追従しない。Drive で直接リネームすること。

配色そのものを増やしたい・色味を変えたい場合は `src/css.html` の `[data-accent]`
（明暗2セット）と `.swatch-*` を足す。`src/js.html` の `ACCENTS` に id を加えると
設定タブに並ぶ。3者が揃っているかとコントラスト比は `npm test` が検証する。

アイコンも同様で、`src/index.html` の各タブに `<svg class="icon icon-...">` を足し、
`src/css.html` の `[data-icons]` で表示を切り替え、`src/js.html` の `ICON_STYLES` に
id を加える。

## デプロイ

事前に https://script.google.com/home/usersettings で
「Google Apps Script API」をオンにしておく。

上記「自分用にカスタマイズする」を先に済ませておくと、`setup()` が作る
スプレッドシートに最初から自分のタイトルが付く。

```bash
npx clasp login
npx clasp create --type standalone --title "家族麻雀 スコア記録" --rootDir src
mv src/.clasp.json .clasp.json    # ← 下記の注意を参照
npx clasp push
```

> **注意**: `--rootDir` を指定すると clasp は `.clasp.json` を **rootDir の中**
> （`src/.clasp.json`）に作る。しかし `clasp push` はカレントディレクトリの
> `.clasp.json` を探すため、そのままではプロジェクトルートで
> `No valid .clasp.json project file` になる。上記のように1つ上へ移動すること。
> `rootDir` の値は `"src"` のままでよい。

1. GAS エディタで `setup()` を **1度だけ実行**
   → スプレッドシートが新規作成され、初期シートとデフォルトルールが投入される
   → **実行ログに「次にやること」が表示される**。発行されたパスワードと、
     現在のタイトルがそこに出るので、必ず目を通すこと
2. 「デプロイ > 新しいデプロイ > ウェブアプリ」を選択
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
3. 発行された URL とパスワードを家族に共有する

`.clasp.json` は Git 管理外。`.clasp.json.example` を参考に作成するか、
`clasp create` が生成したものをそのまま使う。

## 更新するとき

```bash
npm run deploy                # テスト → push → デプロイ更新
npm run deploy -- "変更内容"   # 説明を付ける場合
```

URLは変わらない。

> **重要**: `clasp push` だけではコードは公開されない。Web App は作成時の
> **バージョンに固定**されており、push はプロジェクトにコードを保存するだけなので、
> デプロイを更新しない限り古いコードが動き続ける。症状が「変更が反映されない」
> としか見えず原因を見失いやすいため、この2つは必ずセットで実行すること。

初回実行時に、更新対象のデプロイIDが `.clasp-deployment.json` に記録される
（Git管理外。**デプロイIDは公開URLそのもの**なので、コミットしてはいけない）。
デプロイが複数ある場合は候補が表示されるので、更新したいものを同ファイルに
`{"deploymentId": "..."}` の形で書く。

エディタから手動でやる場合は **デプロイ → デプロイを管理 → 鉛筆アイコン →
バージョン「新バージョン」→ デプロイ**。「新しいデプロイ」を選ぶと別URLが
発行されるので注意。

### 反映されないと感じたら

Web App は `googleusercontent.com` の iframe 経由で配信されるため、ブラウザに
古いHTMLが残ることがある。まず**強制リロード**（Mac: `Cmd + Shift + R`）を試す。
それでも変わらなければ、デプロイのバージョンが古い可能性が高い。

## パスワード

公開範囲は「全員（匿名アクセス可）」でなければ家族がGoogleアカウントなしで使えない。
その代償として、**URLを知っている人は誰でも閲覧・登録・編集・削除ができてしまう**。
パスワードはそこを塞ぐための唯一の鍵になる。

`setup()` がランダムなパスワードを1つ発行し、実行ログに出す。デプロイ直後に無防備な
時間帯を作らないための措置なので、**パスワードなしで運用することは想定していない**。
控え忘れた場合は GAS エディタの「実行数」からログを見直すか、下記の手順で作り直す。

**設定タブの「パスワード」**から、覚えやすいものに変更できる。

- 6文字以上60文字以内
- 一度入力すればその端末には記憶される
- 変更すると他の端末では再入力が必要になる
- アプリからは**解除できない**（解除は下記のエディタ操作でのみ可能）

### 締め出されたとき

パスワードを全員が忘れた場合は、GAS エディタで
**プロジェクトの設定 → スクリプト プロパティ** を開き、`PASSCODE` を削除する。
その後 `setup()` を実行し直すと新しいパスワードが発行される。データは失われない。

### 守れる範囲

| 想定する脅威 | 守れるか |
| --- | --- |
| URLが流出して第三者に開かれる | ○ |
| 総当たりでパスワードを破られる | △ 回数制限がないため、短いパスワードは危険 |
| 家族の端末そのものを他人に触られる | × パスワードは端末に平文で保存される |
| 家族の誰かが他人の対局を書き換える | × 個人単位の権限は無い |

**パスワードを知る全員が全データを編集・削除できる。** 誰が記録したかに関わらず
区別はないので、閲覧だけ許したい相手には渡せない。

総当たりに対する回数制限は実装していない。6文字という下限は入力の手間との妥協点であって、
総当たりを防ぐ強度ではない。外部に漏れうる環境では長めのものを選ぶこと。詳しくは [DESIGN.md](DESIGN.md) §10 を参照。

## 運用メモ

- ルール（人数・配給原点・返し点・ウマ・飛び賞）はアプリの「設定」タブで変更できる。
  スプレッドシートの `Rules` シートを直接編集しても同じ
- ルールを変更しても過去の対局は影響を受けない。対局ごとに登録時のルールが
  `Games` シートに記録されている
- 対局の**削除**は論理削除。行はシートに残るため、誤削除は `deleted` 列を `FALSE` に
  戻せば復旧できる
- ただし対局の**編集**は元に戻せない。`Results` の該当行は書き換えではなく
  削除・再作成されるため、編集前の素点はどこにも残らない
- 収支は必ず合計 0 になる。合わない場合は素点の入力ミス（登録時に警告が出る）
